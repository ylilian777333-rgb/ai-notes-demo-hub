PRODUCT PLAN

OS5：把"个人知识库"
从存得下，做到调得动。

本程聚焦一件事：把"个人知识库"立起来——让用户随时写得进、AI 整理得好、需要时调得出，且拿到就能用。核心判断：写得进不是稀缺能力，调得动才是；资源优先投入"调得动"及支撑它的地基。

00
主张：从"存得下"到"调得动"
一句话

笔记 ＝ 你可控的个人知识库。真正决定价值的，不是"能写多少进去"，而是"需要时调得出、且拿到就能用"。

写进去 → AI 变结构 → 调出来用，三段缺一不可；但本程把投入压向后两段——"写"在生态中并不稀缺，"调得准、调得动"才是笔记不可替代的地方。

核心判断

用户的痛点不在"记不下"，而在"用不起来"：开会录了音、事后查找却要翻找许久；上了二十节课，期末面对几十分钟录音难以复习。这些痛点全部发生在调用侧。写入门槛低、通道多本身不构成壁垒——微信、便签、备忘录都能随手记。所以本程的最优先级，放在让内容"调得出、拿来即用"。

01
定位与护城河
"系统级记忆 / 用户画像"交给系统和小爱在背后建模，笔记不越位、不重复造。笔记专注做"你自己可控的那一份库"。个人知识库赛道已相当拥挤，笔记的不可替代性需要明确回答。以下四点构成其核心壁垒。
笔记的四个不可替代点

🔒 你可控的私域库

系统记忆是"系统替你建模、用户不可见、不可控"；笔记是用户可见、可改、可删、可授权的那一份。可控性本身就是差异化——尤其在隐私敏感的内容上。

🧩 全端 + 全生态的沉淀池

录音、手写、拍照、文档、各 App 经 MCP 汇入——笔记是这些异构输入唯一"留得下、调得出"的落点。瞬时对话不承接用户主动留存的长内容。

🤝 与小爱互补

小爱做"懂你"（瞬时、对话态），笔记做"你的库"（沉淀、可调用态）。笔记是小爱产出的留存与再利用层。这层协同关系要在产品上显性表达。

⚡ 拿到即用

别家知识库止于"搜得到"。笔记要做到调出来直接是待办 / 复习大纲 / 摘要等成品——少一步操作，就是壁垒。

一个必须先对齐的决策

笔记能不能只读引用小爱对用户的理解，直接决定"调得准"的天花板。这是一条必须厘清的边界，需要在 OS5 启动前与小爱 / 系统侧明确对齐：哪些记忆可被笔记只读取用、以什么形态。该边界明确后，"懂你"方能在笔记中真正落地。 这是依赖外部团队的前置项——存在兜底（先以库内 RAG 落地），但对齐进度直接决定"调得准"的上限，是本程最大的交付风险。

为什么"懂你"靠 RAG 先行落地

先用"库内 RAG"在笔记自己的数据上把"懂你"建立起来——不依赖系统记忆即可运转，形成可用基线；再通过"小爱记忆只读引用"逐步增强。边界清晰，飞轮持续。

03
四个工作重点
围绕"写进去 → 变结构 → 调出来用"，本程工作拆为四块重点并明确优先级；另有一道贯穿"写"与"调"的承接层，因其相对独立，单列于 04。
重点一 · 地基：结构化 + 数据打通

🧩 全库数据打通 P0 地基

"调出整个库"的前提是全库统一。当前首页 AI 与详情页 AI 是两套独立数据、未打通——这是地基里的硬阻塞，必须先解。

🔎 可检索索引 P0 地基

把承接层打好的标签与结构，建成能被精准检索、能被 RAG 调用的索引。当前标签只是固定 5 个枚举，不足以支撑"像数据库一样检索"——需要实体 / 时间 / 来源的多维索引。（打标签在 04 承接层）

重点二 · 调得动：让内容拿来即用

🎯 RAG + 一问就答 + 生成产物 P0 核心

对库里内容问一句就答；写新笔记时引用你库里的相关内容（标来源、可核对、可一键去掉）；一键生成待办 / 复习大纲 / 摘要等能直接用的成品。这是本程的核心价值。

🔗 自动关联 + 相关推荐 P0

写或看一篇时，自动浮现相关的旧笔记、录音、文档，让"库"的价值在使用现场被感知到。

重点三 · 写入门控随通道内建
开放写入 ≠ 无门槛写入

降低记录门槛、打开写入通道（含 MCP 外部 Agent 写入）是必要的；但通道一旦放开，"什么都往笔记里写"会让库迅速失去价值感。所以门控必须随通道一起内建——门控只管"入口：要不要写"：意图判断、空内容与噪声拦截、对 MCP 外部写入加可信来源校验与配额。写进来之后怎么归位、要不要并到已有篇，是 04 承接层的事。写入通道有多宽，门控就要有多严。

重点四 · 守住一个"回报锚点" + 诚实分人群

👁️ 留一个"看"类成品 体感

调出来如果只剩"搜到 + 答出"，用户对"库"的回报感不足。保留脑图 / 结构化摘要作为低成本的"看"类成品，维持"值得记"的体感，驱动持续写入。

🎓 明确本程优先人群 对齐

本程的"调得动"最先满足上班族 + 重度用户（会议→待办→问答→汇聚）。学生的"复习播客"等更重的产物放后续，规划里明确标注，不对所有人群过度承诺。

04
笔记内的智能管理：写进来的，自动归位
内容写进来之后，若仍需用户自行分类、整理、排重，库很快会沦为"内容堆积、却难以调用"。"写"和"调"之间必须有一道"智能承接"层——写入即归位、同主题合并、自动打标签、自动起标题摘要，让库始终保持整洁、随时可调，用户几乎无需花费精力管理。（"要不要写"的入口拦截在 03 门控，不重复。）
承接层做的四件事

🗂️ 写入即归类归档

内容进来自动判断类别，归入或新建对应文件夹（工作 / 学习 / 生活…），用户不手动分类。

🔗 同主题合并去重

先搜后写，同主题追加到已有笔记、不重复建篇；识别重复内容自动合并，避免一个主题散落多篇。

🏷️ 自动结构化标签

多维标签（主题 / 实体 / 时间 / 来源），让内容可被精准检索与关联——这也是"调得出"的料。

📝 自动标题 / 摘要

写进来的内容自动起一个能扫读的标题和一句话摘要，列表中清晰可辨、调用时便于定位——这是"调得出"的入口。

承接是"写"和"调"之间的桥

整理由 AI 承担，用户专注于写与用。承接做得扎实，库无需用户维护、调用也更顺畅——它将随手记录的零散内容，沉淀为随时可调用的库。

05
需求清单与优先级
需求优先级为什么
全库数据打通（首页AI ↔ 详情AI 统一底座）P0 地基两套独立数据不通，"调出整个库"在架构上不成立。
结构化 + 索引做厚（多维标签 / 实体 / 时间）P0 地基RAG 检索的依据来源于此；固定 5 标签不足以支撑检索。
RAG + 一问就答 + 一键生成产物P0 调得动本程的核心价值。标来源、可核对、可撤销。
写入门控随通道内建（意图判断 / 空内容噪声拦截 / MCP 可信校验）P0 守底线通道有多宽，门控就要有多严，防止低质内容入库。
智能整理（承接层）：写入即归类归档 / 同主题合并 / 标签与标题摘要P1 承接将写入内容自动整理为可调用状态，用户无需操心收纳。
记忆边界对齐（笔记可只读引用小爱记忆）P1 前置启动前与小爱对齐，决定"调得准"天花板。
降低记录门槛：空页起手式 / 一句话成稿 / 随写随帮P1 写得进起笔门槛是真实痛点，降低后可持续供给内容。
开放写入通道：全生态一键存入 / MCP 写入P1 写得进打开通道，但必须与门控同时上线。
自动关联 + 相关推荐P1 调得动在使用现场让"库"的价值被感知。
回报锚点：脑图 / 结构化摘要P2 体感保留一个"看"类成品，维持"值得记"的体感。
文档 / 链接解析打通P2 配套写入完整性的补点。
小爱入口显化"存进 / 调出笔记"P2 配套在高频入口表达与小爱的协同。
体验打磨：录音转写 / AI编辑 / 搜索 / 性能P2 持续留存的根本。

06
落地节奏
按"先打地基、再做调用、最后补体感"的顺序推进，每个阶段都有一个可验收的里程碑。
阶段一 · 地基
把库立稳
  • 首页 AI 与详情 AI 数据打通，统一底座
  • 多维结构化 + 可检索索引上线
  • 写入门控（意图 / 噪声拦截）内建
  • 智能承接：自动归类归档 + 同主题合并上线
  • 记忆边界与小爱对齐
  • 里程碑：全库可被统一检索
阶段二 · 调得动
让内容拿来即用
  • 库内 RAG + 一问就答
  • 一键生成待办 / 摘要 / 复习大纲
  • 自动关联 + 相关推荐
  • 开放写入通道（含 MCP，门控随行）
  • 里程碑：库内问答可用、产出可直接用
阶段三 · 体感
打磨与回报
  • 保留脑图 / 摘要"看"类成品
  • 录音转写 / AI 编辑 / 搜索 / 性能打磨
  • 小爱入口显化笔记能力
  • 智能整理与门控效果持续复盘
  • 里程碑：留存与调用率双升
一句话收束

本程不扩张范围，聚焦一件事——把"个人知识库"从"存得下"做到"调得动"：先把地基（结构化 + 数据打通）打稳，将资源集中于不可替代的"调得动"上，同时守住写入质量这条底线。
