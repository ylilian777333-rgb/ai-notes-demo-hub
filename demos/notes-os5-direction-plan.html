笔记 = 小爱"懂你"的个人内容层

OS5 这一版的重心，是把小爱做成全生态的系统级 AI——会说、会办事、跨端、懂用户。要让小爱更懂用户，除了系统侧的偏好记忆，还需要一层用户主动认可、看得见、改得动的个人内容。这一层，正是笔记能承接的。本稿梳理笔记在其中的角色、与小爱的衔接、需求重点，以及需要一起共建的接口。

定位笔记是小爱可调用的个人内容层
主线写得出 → 收得进 → 用得上 → 自己长
需共建笔记 ↔ 小爱 的内容衔接
00
笔记在 OS5 里的角色
把笔记放进 OS5 这条全生态 AI 主线里看，它承接的是哪一层
小爱负责"说"和"调度"，笔记负责"沉淀"和"供给"。两者不是并列的两个模块，是同一个飞轮的两半。

OS5 的重心是把小爱做成系统级 AI——基础体验是地基、互联是手脚、AI 是本体。要让小爱更懂用户，除了系统侧的偏好记忆，还需要一层用户主动认可、看得见、改得动的内容。这一层正是笔记能承接的，也是笔记和这条全生态 AI 主线自然衔接的地方。

目前小爱的记忆 / 个性化和笔记的内容是两条线，彼此还没打通。把它们衔接起来——让用户存进笔记的内容能被小爱用上——是这一版笔记可以和小爱团队一起补强的地方，也让笔记的角色更清晰。

01
站位 · 小爱与笔记的分工
一个是入口和大脑，一个是个人内容层；合起来才是"懂你的全生态 AI"
入口 · 大脑

小爱

用户开口说话的入口，理解意图、调度服务、跨端协同、把事办成。它负责"说什么"和"做什么"。

沉淀 · 供给

笔记

用户主动沉淀的、看得见能管理的个人内容；被结构化、可检索，供小爱随时调用。它负责"记住什么"和"调出什么"。

这条飞轮你早就有了，只是没接到小爱身上——四个环节，环环都是和小爱的承接点：

01 写得出

第一篇

小爱帮你起手、把内容写出来、改好

02 收得进

有内容进来

接住小爱的产出：小爱说完 / 生成完，一键沉淀进笔记

03 用得上

被调用

供小爱调用：回答、写作时引用你笔记里的内容

04 自己长

越用越懂

内容越攒越多 → 小爱越用越懂你

关键区分（化解之前的边界）：笔记不做隐式行为画像 / 黑盒系统记忆（那是小爱系统侧的事）；笔记做的是"用户主动存的、显式的、看得见管得着"的那部分个人内容——这恰恰是它和小爱黑盒记忆的差异化价值。
02
四环承接 · 每一环和小爱怎么接
每一环对应一个和小爱衔接的重点，不铺场景
飞轮环节和小爱怎么承接这一版的重点需求
① 写得出小爱帮你起手第一篇、随写随改，AI 从二级页搬到你正在写的地方空白笔记 0→1 起手式 · 文字笔记 AI 化（扩写/精简/成稿）
② 收得进接住小爱与全生态的产出——用户判断有价值，一键沉淀进笔记全生态一键存入（小爱/三方/MCP 产出）· 打通文档 & 链接解析
③ 用得上供小爱调用——小爱回答、写作时引用笔记内容，标来源、可核对（和小爱衔接最直接的一环）AI 搜索已上线，补：把检索接给小爱调用（标来源） · 写新内容时自动关联旧内容
④ 自己长内容越多，小爱越懂你——主动浮现、定期回顾、越用越贴合相关场景主动带出 · 定期回顾 + 到期提醒
四环里，"用得上"是笔记和小爱衔接最直接的一环——让存进笔记的内容能被小爱调出来用。建议这一环优先做实，其余三环按飞轮顺序补。
一条完整的例子（四环怎么转起来）：你随口对小爱说几句对一篇直播文章的想法，小爱帮你起个头 → 这些零散的话一键存进笔记，被理成初稿（写得出 + 收得进）→ 过几天写正式稿，小爱自动引用你之前存的《直播复盘》里的原话，并标明来源（用得上）→ 存得越多，小爱越清楚你关心什么、写东西越像你（自己长）。这条循环里，小爱是入口和笔，笔记是内容的来处和去处。
03
跨设备 · 内容随处记、随处调
笔记的内容天然是跨端的；小爱在哪台设备，笔记内容就该在哪台被记进来、也能被调出去
小爱负责跨端的交互和执行，笔记负责跨端内容的统一沉淀和供给——一份笔记，所有设备同一份。
  • 随处记（采集跨端）：手机、手表、车机、耳机、平板，哪个顺手用哪个——说一句、拍一张、存一篇，都进同一篇笔记。
  • 随处调（调用跨端）：在任意设备让小爱调出笔记内容——车上让小爱念今天要点、平板上调出课堂笔记复习、复诊时手机调出健康档案。
  • 承接跨端产出：小爱在任意设备产出的内容（车机串好的要点、平板生成的大纲、手机拼好的游记），用户判断有价值，一键沉淀回同一篇笔记。
依赖与协作：这一层走 OS5 "跨端同步的记忆"通道——笔记内容端到端加密同步、多端一致、离线可用，和小爱团队的跨端基建对齐，不重复建。配套场景：开会办公、上课学习、看病陪诊、出行旅游、随身灵感这 5 个跨端场景，就是这一层的具体体现（已有单独方案与原型）。
04
和小爱的衔接 · 复用已有的搜索与 tools
笔记语义搜索已合入、承接方式也已定（笔记把能力做成 tools 给小爱调用）；这一版重点是补能力 + 对齐授权，不是重做
笔记的 AI 搜索 / 语义搜索已经上线（支持同义词、时间、人名），和小爱的承接方式也已经定了——笔记把能力做成 tools 提供给小爱调用。所以"供小爱调用"在机制上已经走通，这一版重点是把能力补全、把授权对齐。
  • 已上线AI 搜索 + 承接机制：AI 搜索 / 语义搜索已上线（同义词扩展 + 时间理解 + 人名关联），用户已能在笔记里 AI 搜；承接方式已定——笔记提供 tools 给小爱（miclaw）调用，不用另造一套接口。
  • 要补 1把更多能力包成 tools：除了搜索，把"按范围检索 / 写入 / 关联"等也提供给小爱调用，调用结果标来源、可核对。
  • 要补 2接住小爱产出：让"小爱来源内容滚动更新进已有笔记"落地（《笔记接入 miclaw 来源内容》目前 P0、尚未启动）——这是"收得进"的关键承接。
  • 要补 3对齐授权口径：哪些笔记可被小爱调、用户随时可见、可关、可撤回；和记忆 / 安全对齐"笔记显式内容"与"小爱黑盒记忆"的边界。
现状判断（已核对二期需求合集）：搜索已合入、tools 承接机制已定，所以"供小爱调用"不用重做。这一版重点是把能力补全（写入 / 关联）、把"接住小爱产出"做起来、把授权口径对齐——以补全和对齐为主，工作量和风险都更低。
05
边界 · 做什么，不做什么
把界划清，既不越位，也守住差异化价值
　内容
笔记做用户主动存的、看得见、改得动的个人内容；把它结构化、可检索、可供小爱调用
笔记不做隐式行为画像 / 黑盒系统记忆（小爱系统侧负责）· 默认全收（口径是用户主动挑有价值的存）
笔记是"用户认可、可编辑"的那层个人内容，不是后台默默收集的画像。这既是和小爱清晰的分工，也是用户愿意长期用笔记的信任前提。
06
需求拆分
按四环 + 跨设备 + 接口，把这一版要做的具体需求列清楚
模块具体需求优先级
① 写得出空白笔记 0→1 起手式（空页引导 + 起手式 + 语音入口）P0
　文字笔记 AI 化（扩写 / 补全 / 精简 / 换语气 / 一句话成稿）P0
　AI 入口从二级页前置到编辑页P0
② 收得进全生态一键存入（小爱 / 三方 / MCP 产出 → 笔记）P0
　小爱 / Agent 来源内容滚动更新进已有笔记（不每次新建）P0
　打通文档 / 网页链接解析P0
　多模态导入补齐（图片、录音已具备）P1
③ 用得上笔记 AI 搜索 / 语义搜索（用户已能在笔记里 AI 搜）已上线
　把检索作为 tool 接给小爱调用，标来源、可核对P0
　写新笔记时自动关联相关旧内容、相关推荐（依赖 AI 搜索，可接着做）P1
④ 自己长相关场景主动浮现相关笔记P1
　定期回顾 + 待办 / 日程到期提醒P1
⑤ 跨设备笔记内容多端实时同步、一份内容多端一致P0
　跨端采集（手表 / 车机 / 耳机 / 平板 记入同一篇笔记）P0
　跨端调用（任意设备让小爱调出笔记内容）P1
⑥ 接口把笔记能力做成 tools 提供给小爱（搜索已合入，补按范围检索 / 写入 / 关联）+ 对齐授权口径，和小爱 · 记忆 · 安全对齐边界P0 前置
读法：⑥接口是前置项（跨团队，越早对齐越好）；③用得上是和小爱衔接最直接的一环，建议优先做实；其余按飞轮顺序补。跨设备（⑤）和小爱团队的跨端基建对齐推进。
收口：笔记 OS5 的方向，是把自己和小爱衔接起来——成为小爱可调用的个人内容层。接口对齐、内容能被用上、且能跨设备随处记随处调，笔记的价值就从"好用的记录工具"，延伸到"让全生态 AI 更懂用户"。
