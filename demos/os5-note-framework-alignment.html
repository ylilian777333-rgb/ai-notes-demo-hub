OS5 · 笔记

主框架与思路（对齐版）

按 9/10 两次沟通的结论重写：底 tab 两个、洞察页照相册的组织方式、三个品类各自回答"进去消费什么"、学习备考走通全场景链路。这一版只对齐一级架子和思路，屏内细节后面再补。

2026-09-10 · 内容助手

01

为什么必须换框架

三个用户身上真实发生的事，指向的是同一件事：内容按时间一篇篇排下去，就没法用。

一摞一米高的笔记本

开会只能用纸笔，记了很多年，桌上堆到一米高

想找去年某个会上记的一段，翻不到。

问题：按时间一摞摞堆上去，无法回溯，也就没法消费。今天笔记里那个流是一样的。

写一次作业要翻半个书包

书包里十几本书、一堆本子、一摞卷子

写数学作业要同时拿出课本、卷子、草稿纸、这门课的课堂笔记，写完塞回去，第二天再来一遍。

问题：同一门课的东西本该在一起。老师留的作业、发的教材，都应该自动落到这门课下面。

没做完的待办天天重抄

今天十件事写一页，第二天先把昨天没做完的抄到前面

没人会翻回上周那一页去看有什么没做完，只能重抄一遍。

问题：待办不该靠人搬。它要自己滚到今天，带时间的要自己进日历。

只要还是"单篇笔记按时间排"，上面三件事一件都解决不了。

所以笔记里的内容分成两层：用户记下的原始内容，和整理加工后可以直接消费的内容。日常打开笔记要看到的是后者——它需要一个自己的位置，而不是混在原始笔记流里。

"我不认为用户会消费原始笔记 …… 那他应该消费的就是我说的这个洞察，那么你就应该让我非常好地能消费它，而不是让我去找。" 9/10 沟通
02

一级框架

底 tab 两个：洞察、笔记。创建两个入口：一个建文字笔记，一个进录音。分类层级只保留一层。

这一层 定下来的
底 tab 洞察（整理加工后可消费的内容）／笔记（原始记录，含原有文件夹）。两者不再混在同一个 tab。
创建入口 两个：加号建文字笔记、另一个进录音。原来的第三个按钮去掉。
分类层级 顶栏分类、侧边栏分类、底 tab 三层同时存在过于复杂。建议只留底 tab + 洞察页内的品类分栏，顶栏与侧边栏都收掉；原有文件夹放进"笔记"tab。
洞察页的组织 参照相册：按品类分栏 → 栏内横向滑动 → 每个格子是一个能直接消费的单元（一门课、一次访谈、一段时间的工作想法）。格子要有起好的标题，看得出里面是什么。
格子里默认给什么 默认仍以整理好的正文为主（成本可控），但要能显性换成 PPT / PDF / Excel 等形态，不是只能停在文本。原始那几篇退到次级入口。
做完要通知 一段内容被聚合、加工完成，要主动推送提醒，不靠用户自己回来发现。
洞察首页
品类分栏 + 横滑格子。哪个品类有内容才出现，没有的不占位。

03

三个品类，各自进去消费什么

本版只做这三个。每个品类先拆子品类，再回答用户进去要干什么、所以长什么样、给什么功能。

品类 子品类 进去要干什么 长什么样 · 给什么功能
学习备考 一门课一个格子
大学物理 / 概率论 …		 考前把这门课过一遍，抓考点，检查会不会
  • 自动聚齐四类来源：课堂录音、课件、电子教材、往年真题
  • 进来先给精讲、快讲、出一套卷子，不是一串录音列表
  • 考点大纲 / 按章节 / 按堂次三种看法，每个考点回到原文那一段
  • 老师发的课件、群里发的作业，存下来自动落到这门课
想法随记 工作想法 / 生活随记 / 兴趣（钓鱼、游戏…）
工作和生活不混在一起		 接着往下想，把思路理清楚
  • 进来直接是对谈，内容已挂载并显性标出（＋已挂载 24 条），是一个能接着聊的会话
  • 指出反复出现的那几处，每条回到原文
  • 聊完能落成一份东西：阶段总结、成长记录、分步计划
  • 子品类怎么分需要定：预置几个，还是按用户内容长出来
待办日程 今天 / 本周
按时间，不按来源		 知道现在该做什么，不错过时间
  • 没做完的自己滚到今天，不用重抄
  • 各来源（说的、录音里、图片里）识别出来汇到一处
  • 带时间的进日历、到点各端提醒，完成状态跨端同步
  • 待办本身在待办中心消费，洞察里只给一个入口格子——这一处待定
04

全场景链路：学习备考走一遍

从用户视角看是一件事，不分哪块是笔记的、哪块是日历的。下面标出每段谁交付。

笔记（我们） 其他业务
相册
拍下或截屏课程表，相册里出现「识别课程表」一键把整学期课程导进日历。
日历
课程日程有专属样式，认得清"一门课"和"一堂课"点进去不是编辑界面：先是这堂课在哪上、几点、什么课；下面是这门课上了多少堂、还剩多少、作业完成到哪、笔记链接在哪。
小爱建议
上课前主动提醒今天有几堂课、该去上了。
笔记
到点自动录音，忘了点也不丢循环日程标为自动录音，到时间自己开始；配合端侧低功耗的持续预录，等想起来点录音时，前面那段能接上。这是这条链上我们最关键的一环——用户最容易忘的就是开录音。
笔记
存进来的东西自动归到这门课老师发的课件 PPT、群里发的作业文档，用户存下来就落到对应课程下，不用他管存到哪了。
笔记
两三堂课之后，洞察里长出这门课四类来源聚齐，标题起好，做完推送通知。
笔记
进去就能复习：精讲 / 快讲 / 出一套卷子作业可以结合课上内容一起写。
日历
写完的作业链接回到日程下次看日程时，能看到下一堂课在哪、作业写到什么程度、这门课的笔记入口。
"你这边是利用这个课程表，怎么把录音给录好？录好以后怎么把一节课变成一门课，对不对？这是一连串下来的。" 9/10 沟通
05

本版不做

范围收到三个品类，其余先不铺。

不做

  • 生活管理：记账、拍小票、健康趋势。优先级不高，后面再说
  • 通用场景兜底：不再单独设计"其余内容"的一套形态。三个品类做透之后，通用的怎么处理自然清楚
  • 卡证与账单：本版不排期

人力压在这三个品类上。原来的方案里这几块已经画了稿，先留着不排期，等三个品类跑通再看要不要接上。

卡证虽然不做，但它定义了什么叫"够极致"

这一版的设计基准照它来对：

  • 拍到的、存下的、别人发来的，都能漂亮地聚在一处——设计过的证件样式，一眼分得出身份证和银行卡，不是一串信息条目
  • 记不住时随时来看，好读，形成鲜明印象
  • 问小爱的时候取得出来、用得上
  • 要填号码的时候能直接填
06

这几处想跟你对一下

待办日程进不进洞察 tab 洞察里放的是加工后可消费的内容，待办是清单，性质不太一样，而且它最终在待办中心和日历里消费。是在洞察里留一个入口格子（今天 4 件），还是干脆不进洞察、只在待办中心和日历？
课程和访谈合不合成一个品类 两者是同一个模式：同一主题多次记录 → 聚成一个格子 → 出一份能直接消费的东西。合成一个（比如"课程与专题"）能省一层设计；分开则课程可以做得更专。
顶栏和侧边栏收哪个 我的建议是两个都收，分类只留洞察页内的品类分栏，原有文件夹放进"笔记"tab。这样只剩一层分类。
随记的子品类怎么定 工作、生活、兴趣是预置好的固定分栏，还是按用户实际记的内容长出来（钓鱼、游戏这种）？预置好理解、但可能空着；长出来更贴合、但冷启动时洞察页是空的。
