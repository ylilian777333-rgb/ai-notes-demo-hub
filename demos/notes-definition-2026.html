01
用户的真实处境：记了一堆，却用不起来
先不谈产品，先听用户怎么说。下面四个人，是笔记每天面对的真实场景。

👨‍💼 上班族

"开了一上午会都录了音，下午客户问起上周的决议，我翻了十分钟没找着。"
痛点：记是记了，要用的时候用不起来。
想要：问一句就答，自动帮我列出待办。

🎓 学生

"这学期录了二十多节课，期末想复习，点开全是几十分钟的录音，根本没法看。"
痛点：记下来的是原始素材，没变成能用的东西。
想要：变成复习大纲、考点，最好还能听。

🧑 普通人

"想记点东西，还得开 App、新建、一个字一个字敲，常常懒得记，或者记一半就放下了。"
痛点：记的门槛太高，经常起不了笔。
想要：随口说一句，就帮我记好、写顺。

🗂️ 重度用户

"东西记在便签、记在微信、记在备忘录，到处都是，真要用的时候想不起在哪。"
痛点：散在各处，等于没记。
想要：值得留的都汇到一处，随时调出来用。
共 性 洞 察

没有人真正想要"管理笔记""给笔记分类"。大家要的是同一件事——我随手记的东西，能攒成我自己的一个库，需要时随时能调出来用。

02
所以，笔记该是什么
顺着洞察往下推：用户要的，是"我的东西攒成一个库、随时能调来用"。那笔记的定位就清楚了——
一 句 话 定 位
笔记 = 你自己的个人知识库。
你随时随地能往里写，AI 把它变成结构化、能查能调的内容，需要时随时调出来用。
它的运转，就是三件事接起来：随时能写进去 → AI 变成能用的结构 → 随时能调出来用（第 03 节展开）。这里的关键是想清楚什么不做——尤其"系统级记忆 / 画像"那类，是系统和小爱的事，笔记不越位。

✕ 笔记不做（不越位）

  • 不做系统级记忆 / 用户画像：那是系统、小爱在背后给你建模的事，笔记不抢、不重复造。
  • 不做要你操心的收纳箱：整理交给 AI，不让用户花精力分类管理。
  • 不做团队协作：只聚焦个人，不碰飞书 / 钉钉的事。
  • 不做记完只能翻的记事本：调不出来用，等于没记。

✓ 笔记要做

  • 你自己写入、自己可控的库：写什么、改什么、删什么，你说了算。
  • 随时随地能写进去：说一句、随手记、各端汇入，别的应用还能通过 MCP 写入。
  • 变成结构化、能查能调的内容：像你自己的一个数据库，不是一堆原始素材。
  • 随时调出来用：搜得到、一问就答、被 AI 拿来写新的、被各场景调用。
和 MiClaw 的关系

笔记是你自己写入、自己可控的个人知识库，也承接 MiClaw 产出的内容供你留存、再用。记忆、画像这类系统级能力不归笔记——笔记做好"你的库"，系统做"懂你"，各司其职、不越位、不重复建设。

03
知识库怎么运转：能写进去 → 变成结构 → 调出来用
把定位讲成一条线。三段都顺，知识库才真正活起来——能写进去的越多、整理得越好，调出来才越有用。
① 写进去

随时随地能写

说一句、随手记、录音、文档链接导入、各端汇入；别的应用 / Agent 还能通过 MCP 写入。门槛越低、通道越多，库才攒得起来。

→AI 整理
② 变成结构

整理成能查能调的内容

AI 把写进来的东西理解、结构化——纪要 / 要点 / 标签，变成像数据库一样能检索、能被调用的内容，而不是一堆原始素材。

→随时取用
③ 调出来用

需要时拿来就用

搜得到、一问就答、被 AI 拿来写新的、被各场景与 MCP 读取调用，生成能直接用的产物。

"调出来用"的产物，按用户怎么消费分四类——这也是需求要支撑的终点：
🎧 听

不便看屏时：播客 / 音频要点

👁️ 看

要呈现时：PPT / 脑图 / 摘要

✋ 做

要执行时：待办 / 日程 / 提醒

🧠 学

要记忆时：复习大纲 / 考点 / 问答

判 断 标 准

用户调出来后，下一步还要不要再做点什么？要，就还没到位；拿到就能用，才算这个库真的有用。

04
OS5 规划：把这个知识库做立起来
这 一 程 想 清 楚 的

今年功能铺开了（从 0 到 1）。OS5 不再铺新摊子，而是把"个人知识库"这件事做立起来——让用户随时写得进、AI 整理得好、需要时调得出，并把已有功能的体验做扎实。

围绕"写进去 → 变成结构 → 调出来用"这条线，这一程的活分四块：
① 重点做：写得进 + 调得出最优先

写得进＝降低记录门槛（说一句就成稿）、打开写入通道（各端汇入 + MCP 写入），让东西源源不断进库；调得出＝搜得到、一问就答、被 AI 拿来写新的。这两头通了，知识库才是活的、才有用。

② 配合补：把"变成结构"做实跟着做

AI 整理 + 结构化 + 可检索做扎实（库的地基）；补文档 / 链接解析卡点；在小爱入口让用户能直接存进 / 调出笔记。

③ 同时打磨：把已有功能做到好用持续做

录音转写、AI 编辑、搜索、性能——"有了但还不够好用"的，持续打磨。体验是用户留不留下来的根本。

④ 先不做：这一程不碰的往后放

"越用越懂你"的主动服务放下一程；"记忆进笔记"方向没定，先不投；PPT / 播客、出海、PAD 是另一条线。

为 什 么 这 么 排

四个人、一个版本窗口，什么都做，就什么都做不好。把"随时写得进、随时调得出"这个知识库的骨架立起来、做到用户有感，比四条线各做一半值得多。

需求清单：按规划拆解
把上面的规划落成可执行的需求。"重点"两组先做透，"配套"和"体验"跟上，往后放的明确标出。

重点 · 先做
空页起手式
进笔记给一句引导 + 起手式（写一段 / 列清单 / 记要点），点一下就开始，不再对着白板发呆。
新做
工具条随写随帮
看你写了什么，随手给扩写、补全、理顺，全程不切页面。
新做
一句话成稿
给一个主题，直接生成整篇，或先给大纲再展开。
新做
全生态一键存入
小爱、其他 App 产出的内容，用户判断有价值就一键存进笔记。
新做
开放写入（含 MCP）
其他应用 / Agent 能通过 MCP 把内容写进你的笔记，让写入通道真正打开。
新做
调得出 重点 · 需要时拿来就用
重点 · 先做
用你的内容写新的（RAG）
写新笔记时引用你库里相关的内容，标来源、可核对、可一键去掉。
核心
一问就答 + 生成产物
对库里的内容问一句就答；一键生成待办 / 复习大纲 / 摘要等能直接用的产物。
新做
自动关联 + 相关推荐
写或看一篇时，自动浮现相关的旧笔记、录音、文档。
新做
变成结构 + 进得来 + 看得见 配套 · 库的地基与通道
配套
结构化 / 可检索做实
AI 整理成纪要 / 要点 / 标签，让内容像数据库一样能被准确检索和调用。
新做
打通文档 / 链接解析
图片、录音已能导入；文档与网页链接的解析必须打通，写入才算完整。
补卡点
小爱入口显化笔记能力
在小爱对话里就能"存进笔记 / 调出笔记内容"，让能力在高频入口显性可达。
新做
体验与易用性优化 持续 · 把已做的功能打磨到好用
持续打磨
录音转写 / 速记
提升转写速度与准确度，速记进笔记更快更稳。
优化
AI 生成 / 编辑
生成更稳、可控，支持对比与一键撤销，让用户敢用、放心用。
优化
搜索体验
提升召回与排序，搜不到要给反馈和引导，而不是空结果。
优化
首页与基础性能
自动内容不污染首页、不增加管理负担；启动、大笔记加载持续优化。
优化
后置 / 待定 本程不投或待对齐
往后放
主动服务（越用越懂你）
主动浮现、定期回顾、个性化推荐——方向认可，但放下一程，避免本程铺太宽。
