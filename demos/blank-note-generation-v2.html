空白笔记 0→1 生成引导 方案

用户打开一篇空白文字笔记，怎么不用切页面、顺着自己写的，最快变成一篇能用的笔记。这是一切内容的起点——第一篇都写不出来，后面拿它做 PPT、播客、网页就都没内容可用。本方案从只打字用户的真实场景出发，讲清楚空白笔记该帮他们做的三件事：帮你开始、帮你写下去和改好、调你存过的资料帮你写好这一篇。

聚焦文字笔记 / 不用语音的用户
主线先讲用法和需求，再讲做法
不涉及二次消费 · 笔记分类整理
00
核心判断
空白笔记的根本问题不在交互，而在它有没有帮用户"开始"
空白笔记不该是一块空板子。用户写到哪，AI 就在那一步帮一下，不用切到别的页面。
现状问题

AI 都藏在二级页

想用 AI 得先点小星星、进对话框。只打字、不用语音的用户，打开空白笔记几乎碰不到 AI。

机会

边写边帮

用户在空白笔记里一直在打字。把帮助放在他正在写的地方，而不是让他先学会去哪儿点。

做法

顺着内容给

在当前页面，根据用户已经写的内容直接给建议，点一下就用上。用户写什么，就给什么。

    03
    从场景提炼规律
    六个人看着在做不同的事，本质区别只有一个——进到空白笔记时，手上已经有多少东西
    不按"用户是谁"分，按 进来时手上有多少东西 分。同一个人不同时刻也不一样：林姐速记时手上是空的，小王记完想法手上是半句话，大磊想写稿手上是一个题目。
    情况一

    空着，什么都没写

    打开一篇空笔记，想记点什么，但不知道从哪开始。这是每个人进来的第一秒。
    代表：大磊面对空白那一刻 · 多数人进来的第一秒
    AI 该帮 → 给个开头：给几个起手式，或让他直接开口说
    情况二

    只有一句话主题

    心里有个明确题目，但正文还没写。把这句话给 AI，就能要到一整篇。
    代表：大磊"写个开场白" · 小王把想法说成一句
    AI 该帮 → 直接写一篇：一句话出整篇，或先给大纲
    情况三

    写了一半

    已经写了些东西——一句灵感、几条提纲、一段流水账，差的是"接着往下"和"理顺"。这一档最高频。
    代表：小王的灵感 · 陈老师的提纲 · 阿哲的流水账
    AI 该帮 → 接着往下写：顺着已写的扩写 / 补全 / 理顺
    情况四

    贴了一大段

    把外部一大段内容贴了进来，原始、读不进去，要 AI 帮忙提炼或换个形式。
    代表：小悠粘贴课本 / 摘抄资料
    AI 该帮 → 帮你提炼：总结 / 划重点 / 转问答 / 转表格
    林姐是个例外，要单独对待：她"空着"不是卡住，而是只想快速记一笔——本方案的生成建议不服务她。速记要的就是快，AI 只在认出电话 / 地址 / 时间时给个轻动作，别弹生成建议去打扰她。
    04
    解法 · AI 在三个时刻帮你
    写一篇笔记是有过程的：从空着，到写一点，到一段成形。AI 就在这三个时刻分别帮一下，全程不用切页面
    ① 帮你开始

    不让用户对着空板子

    • 空页面中间给一句引导，不再一片空白
    • 给几个起手式：写一段 / 列清单 / 记要点
    • 语音做成最显眼的入口，进来就能说

    核心 · 同一套工具条，帮你写下去、也帮你改好
    04 里的"帮你写下去"和"帮你改好"，其实是一个机制——工具条看你写了什么，就给对应的下一步
    工具条不是固定的几个按钮。它看你写了什么，就给对应的下一步。

    同一个工具条，面对不同的输入，给的建议完全不同。看三个例子就懂了：

    1用户写下
    家长会发言
    1. 这次成绩
    2. 纪律问题
    3. 暑假安排
    2工具条看出
    这是一份 提纲，只有骨架没正文
    3于是给出
    逐条扩写补全遗漏列成表格
    点"逐条扩写"，三条骨架就地变成完整讲稿
    1用户写下
    选题想法
    直播间的信任是怎么建立的
    2工具条看出
    这是一条 灵感，一句话没展开
    3于是给出
    扩写成段发散3个角度帮我追问
    点"发散3个角度"，一句话变成几条能写的方向
    1用户写下
    复习资料
    （粘贴了一大段课本原文……）
    2工具条看出
    这是 粘贴的长文，原始没加工

    总结划重点转问答卡片
    点"转问答卡片"，一大段课文变成能背的题
    工具条始终跟着你写的东西变——没写完，帮你写下去；写完一段、选中它，就帮你改好（精简 / 换成正式语气 / 总结成一句）。同一套工具条，覆盖 04 说的"写下去"和"改好"两件事。
    说明：这里说的"工具条建议"是帮你写内容（扩写 / 续写 / 整理），和笔记列表里按类型筛选（录音 / 文档 / AI生成）是两回事，别混。
    06
    内容来源 · 用你存过的，帮你写好这一篇
    前面 chips 用的是你"当场写的"；这一节——同一套 chips，素材换个来源：你笔记里"存过的"
    把一篇写好，光靠当场打的字不够，还得用上你存过的东西。同一套 chips、同一个动作——AI 写的时候除了你刚写的，还会调你笔记里相关的内容。你的笔记是别人复制不了的私人资料库，记的越多，写得越像你，你越离不开。
    底层逻辑 · 内容要先"可参考"，再分两种方式用
    AI 读不了音频、读不了 PPT、读不了图片。资料库里的一切，必须先加工成"可检索的文本表示"，AI 才参考得了。这就是"加工"这一环的产品价值——也是为什么播客 / PPT / PDF 要先加工、再进库。
    内容先加工成什么（才可参考）AI 怎么用
    文字 / 手写直接用（手写走 OCR）检索片段、引用
    录音 / 通话转写稿 + 摘要引用"据某次录音"
    播客转写稿 + 分段摘要引用其中某一段
    PPT提取每页标题 / 正文 → 大纲参考其结构、要点
    PDF / 文档解析正文 + 分块引用页 / 段
    图片 / 截图OCR + 图像理解检索提取出的文字
    小爱记忆本就是结构化事实当背景注入，不逐条引用
    数据怎么流：把"资料库"做成"可实时检索的库"
    加工成文本只是第一步。真正让 AI 能"边写边查你全部笔记"的是这条数据链——存进来就建好索引，写的时候按相关性召回，再连同你刚写的一起交给 AI。
    1 入库即加工
    每种内容转成可检索文本（转写 / OCR / 大纲 / 解析）
    →
    2 建语义索引
    让相近意思的内容能被找到，不靠关键词死磕
    →
    3 按需召回
    写作时从整个库挑出最相关的几条
    →
    4 注入生成
    召回内容 + 你刚写的，一起交给 AI 写
    检索范围 = 你的整个笔记库，不用你手动整理——存得越多、召回越准、写出来越像你。这是别人复制不了的护城河。

    它俩和 chips 什么关系？你点一次 chips（扩写 / 成稿 / 对照），AI 在背后同时走两条路取数据，再合成这一段——你只点一下，两条路一起发生，这是它俩最底层的分界：

    方式一 · 当资料引用

    检索片段，标出处

    文档 / 录音 / 播客 / 网页 / PPT / 图片——AI 检索相关片段引用进来、标来源，能点开核对（本质是 RAG）。

    方式二 · 当背景知道

    知道你是谁

    小爱记忆 / 偏好 / 关键事实——AI 写的时候"知道"这些、让内容更像你，但不逐条标"引用自记忆"。

    用户看到什么：取材 → 成文 → 你能核对、能去掉

    取材不是新增按钮——它藏在那套随内容变的 chips 里：点「扩写 / 成稿 / 对照」，AI 就顺带从库里取材。下面用最高频的「写了一半 → 扩写」走一遍完整链路：AI 怎么取、你看到什么、你能怎么管。

    可溯源

    每段都标来源

    用到的每一条都标出处、能点开核对，不想用一键去掉——不黑箱。

    不打扰

    不相关就不用

    库里没有足够相关的，就只用你当场写的，不硬塞、不编造。

    写好的效果 = 引用你的资料 ＋ 知道你的历史
    AI 写得好不好，由两样合成——引用你的资料 ＋ 知道你的历史，两个一起，才是"你的"那一篇。一边从你库里检索相关内容、引用进来标好源（有据、能核对，方式一）；一边带着对你的了解写：你是谁、在做什么项目、以前记过什么（像你、贴合你的情况，方式二）。只引用不懂你像拼凑的资料，只懂你不引用像空谈；两样合起来，才是别人复制不了的"你的笔记"。

    边界与待讨论
    明确不做的，和需要进一步对齐的问题
    明确不做

    ✕ 笔记 / 资料自动分类（边界模糊，不在本方案）
    ✕ 给速记硬塞生成建议，要克制
    ✕ 把帮助继续藏在二级页
    ✕ 拿老用户的旧习惯当未来的设计前提

    待讨论

    · 工具条建议是一直显示，还是用户唤起？
    · 边说边出字的延迟和功耗代价多大？
