#目标
笔记正在从记录工具，变成用户消费 AI 产出物的入口
随着内容来源爆发（MiClaw产出、AI键采集、录音转写、穿戴同步），笔记承载的内容越来越多。
但用户主动阅读笔记正文的频率没有上升——他们真正消费的是 AI 基于笔记产出的最终结果：考点、待办、播客、PPT。
用户写/说/拍
笔记沉淀（中间态）
AI 理解加工
产出最终物（终态）
用户直接消费
#方案
围绕"最终消费物"设计产品。每种笔记都有对应的终态产出——点了就用、不需要回看原文。
课堂笔记
会议纪要
日常速记
待办
播客
PPT
功能 输入（用户做什么） AI 处理 最终产出物（终态） 用户怎么消费
课堂笔记 录音 + 拍照 转写 → 结构化 → 考点提炼 → 出题 考点清单 / 模拟题 / 播客 / 脑图 打开直接复习、做题、听播客
会议纪要 录音 + 拍白板 分议题 → 提结论 → 抽待办 待办事项 / PPT / 播客 待办直接执行、PPT直接分享
日常速记 AI键/语音/分享 识别类型 → 结构化 → 归档 待办 / 知识卡片 / 播客 问AI直接调出、主动提醒
播客 —（基于任何笔记生成） 内容音频化 → 条件播放 播客音频 点了就听、上车自动播
PPT —（基于任何笔记生成） 内容结构转换为演示文稿 可分享的PPT 打开就能讲解/分享
产品定位
自增长可赋能的个人数字资产中枢
自增长：用户每次记录 + 系统自动采集，数据持续积累，AI 对用户的理解不断加深
可赋能：AI 基于积累产出用户可直接消费的最终内容（考点 / 待办 / 播客 / PPT / 卡片）
中枢：用户侧是创作和消费的入口，MiClaw 侧是调用全量数据的底座
#设计策略
4个设计决策，对应4个核心页面。
策略 01
首页：保持框架，增加产出物可见性
不改变用户已有心智。每张笔记卡片新增产出物标签，让用户一眼看到"这篇已经帮我准备了什么"。
策略 02
详情页：产出物在上，原文在下
用户打开笔记首先看到 AI 帮他准备好的东西（考点/播客/PPT/待办），笔记正文在中间，原始转写折叠在底部。
策略 03
AI对话框：产出物生成入口
用户通过笔记底部AI对话框触发生成播客/考题/PPT/待办。保持现有交互模式，零学习成本。
策略 04
侧边栏：三段式分类
笔记来源 / AI帮你做的 / 文件夹。三段各答一个问题，逻辑不混用，与首页一一对应。
设计稿 1：首页 · 笔记列表
保持现有框架不变，每张卡片底部新增产出物标签（考点/播客/PPT/待办）。用户一眼看到价值。
首页 · 默认态
（见右侧设计稿）
设计稿 2：笔记详情页 · 产出物 + AI对话框
打开笔记首先看到 AI 帮你准备的产出物卡片区。底部 AI 对话框是生成入口。原文折叠在最底部。
1. 详情页 · 产出物展示态
用户打开一篇笔记后看到的默认状态：产出物卡片在正文上方，每个卡片可独立操作（查看/播放/做题）
详情页 · 产出物区
（见右侧设计稿）
2. AI对话框 · 展开态
用户点击底部输入框后，上方弹出智能推荐chip：提炼考点 / 生成播客 / 做PPT / 提取待办 / 问问题。点击即触发。
AI对话框 · 展开态
（见右侧设计稿）
设计稿 3：侧边栏 · 三段式分类
侧边栏三段逻辑：
第一段「笔记」= 按来源区分（全部/手写/录音/速记）
第二段「AI帮你做的」= 所有笔记产出物聚合（待办/播客/PPT/考题/卡片）
第三段「文件夹」= 用户自建分组
三段对应关系
侧边栏段落 回答什么问题 包含什么 和首页的关系
笔记 我有多少笔记、从哪来的 全部 / 我的创作 / 录音笔记 / AI速记 = 首页列表的筛选维度
AI帮你做的 AI从我的笔记里产出了什么 待办 / 播客 / PPT / 考点 / 知识卡片 = 跨所有笔记的产出物聚合视图
文件夹 我怎么组织我的笔记 用户自建文件夹（一篇笔记只属一个） = 首页筛选栏的文件夹图标
