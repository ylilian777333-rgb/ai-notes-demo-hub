用 · 工作经营 —— 完整产品方案

TR1 定的是「一个项目的零散笔记一键汇成合计算好的报价单」。这一节把它拆到可交付：逐屏区块与控件、字段与规则、四态与异常、埋点、可测验收。

01场景定义与用户

这一节要回答：谁、多久用一次、内容有多大、现在靠什么撑着。规模数字决定了性能指标和默认值。
项内容依据
典型用户装维 / 门窗安装 / 计件工 / 电厂检修 / 小型工程从业者，一人对多个客户或项目，自己记账自己报价Q2 截图分析，该类内容跨两年以上持续记录，是留存最稳的一批
记录频次每完成一户或一个工序记一次，日均 1–5 条；旺季单日可达 10 条以上同一用户笔记时间序列
单项目规模典型 40–80 条记录，跨 1–3 个月；本方案按 63 条 / 3 个月为基准做性能设计真实样本（城南小区改造 63 条，其中 41 条带数量）
现状做法账目为手写连加算式（3+2+4+1.5=）；流水靠空格对齐成列；无人使用表格；导出为分享图后列错位截图中该类记录无一例使用表格控件
要用的时刻项目结束或月末对账时，需要一份能直接发客户的单子：金额算好、格式整齐、抬头齐全反馈中反复催表格与导出
失败代价金额算错要重新对账并向客户解释，直接影响收款，用户对准确性零容忍决定了「明细与总计不一致时禁止导出」这条硬规则

02本节目标与衡量

目标可测口径目标值
记得动语音记一条工单的端到端耗时（唤起→存入完成）≤ 8 秒
抽得准客户 + 数量 + 单位三项全对的比例（100 条真实口述样本）≥ 85%
算得对总计等于各行小计之和；任一格修改后重算延迟100% 一致，重算 ≤ 200ms
发得出导出文件的行数、列数、总计与预览一致抽查 50 份 100% 一致
省得下生成一份报价单相比手工整理节省的操作步数由 20+ 步降到 4 步以内

03端到端流程与分支

主流程：上门完工 → 语音记一条（D1）→ 存入确认（A2）→ 后台抽字段并归到项目主题 → 需要成列时插表格（D2）→ 月末点「汇成报价单」（G3）→ 选范围与单价（D4）→ 预览校对合计（D5）→ 导出 PDF 发客户（D6）
分支 1：口述里没有数量 → 不出结构预览行，按普通笔记存，不进报价单可用集合
分支 2：出现两个同名客户 → 结构预览行给两个候选让用户点选，不自动挑
分支 3：某客户没有单价 → 该行单价位标黄、不给小计，预览顶部黄条汇总「有 N 行还没填单价」
分支 4：明细与总计校验不通过 → 顶部红条并禁用导出按钮，不产出文件
分支 5：源笔记被改动 → 回到预览时提示「源记录有变化，重新算一次？」，用户确认后重算
分支 6：生成超 5 秒 → 转后台，完成后通知栏提示，界面退出不中断

这是易用性欠账里优先级最高的一条（手机 P00）。用户现在靠空格对齐，本版要给到真正的表格：能增删行列、能拖列宽、数字列能自动合计。

控件与规则

项规格
插入默认 3×3；插入后光标落第一格；空表列头给浅色占位「客户 / 数量 / 单价」，点一下即替换
列类型文本 / 数字 / 日期，按首两行内容自动判定，用户可在列头改；数字列右对齐
增删工具行增行、增列、删行、删列；删除有撤销（5 秒内）
列宽可拖动；最小 64dp；拖动时显示当前列宽；记忆到该表格
横向溢出右侧渐隐提示 + 可滑动，不让用户以为只有这几列；表头固定不随横滑消失
合计选中数字列点「Σ合计」，在列底生成合计行；单元格变化时自动重算；合计行样式加粗、不可直接编辑
小计列可设为公式列（数量 × 单价）；任一因子变化即重算；用户可覆盖为手填并标「已手改」
数值精度金额保留 2 位小数，四舍五入；数量保留 2 位；合计按各行小计求和，不按未舍入原值累加
非法值数字列输入文字：该格标黄，合计跳过并在合计行注明「有 N 格没算进去」，不静默算错
语音填表口述「李工 3 个点数每个 80」按当前列结构填入一行；列对不上时填最近似列并高亮待确认
性能30 行 × 8 列横滑与纵滑 60fps；100 行以内不卡顿；低端机降级为分页渲染

异常

情况处理

08D5 预览与合计校对 · 计算与校验

这一屏的唯一目标：让用户敢把这份直接发出去。每一行能对到原始记录，合计是算出来的不是抄来的。
区块结构规则
顶部提示条黄条：有 N 行还没填单价，可点开逐条处理；红条：明细和总计对不上，先核对一下红条出现时禁用导出按钮
抬头项目名 · 报价单 / 客户 / 日期区间 / 我的联系方式客户名缺失时不允许进入导出
明细表日期 / 客户或工序 / 数量 / 单价 / 小计 / 跳转图标每行携带 source_note_id，点图标回到源笔记；行序按日期升序，同日按记录时间
合计区分项小计（人工 / 材料）+ 总计 + 一行「由 41 条记录合计得出」总计 = Σ 各行小计；计算完成前显示「计算中」而不是 0
修改联动改数量或单价 → 小计与总计立即重算，该行标「已修改」重算 ≤ 200ms；修改只写生成层，不改用户原始笔记
源记录变更从源笔记返回时比对版本号有变化则提示「源记录有变化，重新算一次？」，用户确认后重算
一致性校验行数、各行小计、分项小计、总计四项任一不通过则禁止导出并出红条（对应不变量：明细与总计必须一致）

11规则汇总

规则口径
抽取置信度≥ 0.85 直接填入结构预览；0.60–0.85 填入并高亮待确认；< 0.60 不填该字段，不猜
同名客户不自动消歧，给候选让用户点选；用户选过一次后同项目内沿用
单位不一致同一项目出现「点数」与「个」：不自动换算，分组合计并提示「这两组单位不一样」
四舍五入金额 2 位小数；先算行小计再求和，不用未舍入原值累加
缺失单价不推测、不套用其他客户单价；该行不参与总计，并在顶部汇总提示
不编造明细行必须能定位到源记录；定位不到的行不输出（对应评测门禁项）
修改优先用户手改过的字段与行，后续重算与重生成不覆盖
