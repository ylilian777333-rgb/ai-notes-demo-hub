小米笔记：从定位到需求

MiClaw 内容助手 · 需求导入文档 · 2026.05

一、我们观察到什么

过去一年，笔记APP的内容来源发生了结构性变化。录音转写、AI键采集、穿戴设备同步、分享面板导入——系统侧自动产生的内容，正在取代用户手写，成为笔记的主体。

但数据量的增长没有带来使用频率的增长。用户并不会因为"笔记更多了"就更频繁地打开笔记正文阅读。一篇2000字的课堂转写，用户可能一次都不会通读。

这说明一个问题：用户来笔记APP，并不是为了"阅读笔记"。

那用户来干什么？我们观察到的实际行为是：用户打开的是基于笔记生成的结果——考点清单、待办事项、播客音频。这些东西"点了就能用"，不需要再加工。

核心判断

笔记的价值不在"记住"，在"产出"。
AI基于用户积累的数据，产出用户可直接消费的功能。笔记正文是中间过程，不是最终结果。用户要的不是"一篇写好的笔记"——用户要的是"AI帮我做完了的事"。

这个判断引出一个设计问题：如果不让用户看到原始笔记，而是直接看到消费内容——我们的产品应该怎么构建？

以下所有需求设计，都围绕这个问题展开。

二、产品定位与核心概念

定位

自增长可赋能的个人数字资产中枢。

拆开说三件事：

  1. 自增长 — 用户每次录音、拍照、说话、存链接，数据都在积累。系统侧（AI键、穿戴设备）还在持续无感采集。这些数据不依赖用户刻意整理，自然增长。
  2. 可赋能 — 积累本身没有价值，AI把积累转化为可消费的功能才有价值。数据越多，AI对用户的理解越深，产出越精准。这是飞轮，不是存储。
  3. 中枢 — 对用户来说，这是创作入口（记录）+ 消费入口（使用产出物）。对MiClaw来说，这是它的长期记忆和数据底座——MiClaw回答用户问题时调用的就是这里的数据。

关键区分：原始数据 vs. 消费物

整个产品围绕一个转化链条运行：

用户输入（说/写/拍/存）→ 原始数据沉淀→ AI理解与加工→ 消费物产出→ 用户直接使用

这里必须明确："消费物"不是"换个格式的笔记"。消费物的判定标准是——用户拿到它之后，不需要再做任何加工就能直接用。

消费物AI 加工了什么用户怎么用（终态）
结构化课堂笔记2000字转写 → 按章节重组 → 重点标注 → 照片OCR嵌入打开直接看结论，不需要自己从头整理
会议纪要录音 → 按议题分段 → 提炼结论 → 抽取待办 → 分配责任人开完会就能转发纪要，待办自动跟进
待办清单从录音/截图/对话中识别行动项 → 提取截止日 → 同步日历到期自动提醒，不怕漏事
考点清单 + 模拟题跨多节课聚合 → 提炼高频知识点 → 基于知识点出题直接刷题复习，不用自己总结
播客笔记内容 → 音频化 → 支持条件播放（上车/闹钟后）通勤时听，把文字变成可以"被动消费"的形态
知识卡片跨多篇笔记聚合 → 提炼核心观点 → 生成一张可分享卡片发到朋友圈/群里，输出认知
精准问答用户提问 → MiClaw检索全量资产 → 基于个人数据回答问"我上次体检血糖多少"直接得到答案
注意"课堂笔记"和"会议纪要"的定位：它们虽然仍是文字形态，但已经不是原始录音转写。AI做了重组、提炼、补充——用户打开看到的是结论而不是原始素材。这就是"消费物"的判定——用户不需要再加工。原始转写则折叠进"原文"区域，需要时才展开。

三、场景串联

以下三个场景覆盖笔记产品的核心用户群。每个场景都遵循相同逻辑：用户输入越少越好，AI产出越直接越好，时间跨度越长飞轮效应越强。

场景一：学生上课

用户画像：18-24岁大学生，每天2-4节课，需要高效记录+期末复习

阶段用户做什么系统做什么产出
课前点提醒卡片日历识别课程 → 推送提醒 → 自动新建笔记进入录音待命—
课中录音 + 拍PPT/板书实时转写 + 照片按时间线关联 + 重点标记记录—（原始数据积累）
课后无需操作转写全文 → 分章节 → 生成结构化笔记 → 照片OCR融入 → 提取作业生成待办结构化课堂笔记 + 待办
期末复习"帮我复习高数"跨整学期所有高数课笔记汇总 → 知识点聚合 → 生成考点清单 → 出题 → 生成播客考点清单 + 模拟题 + 播客
飞轮效果：学生记了一学期课 → 期末说"帮我复习" → AI基于整学期积累产出完整复习方案。数据积累了四个月，消费只需要一句话。这是NotebookLM做不到的——它需要手动上传文档，我们全程自动积累。

场景二：职场会议

用户画像：25-35岁白领，每周3-5次会议，痛点是待办跟丢

阶段用户做什么系统做什么产出
会前—推送提醒：会议名 + 参与人 + 上次遗留待办—
会中录音 + 拍白板 + 标记关键决策录音 + 照片按时间线关联—（原始数据积累）
会后无需操作按议题生成纪要 → 提取待办（谁/做什么/截止日）→ 同步日历 → 上岛通知会议纪要 + 待办
跨次回忆"张总上次提了什么意见"MiClaw检索历史会议笔记 → 跨篇聚合 → 精准回答+附来源精准回答
飞轮效果：开了10次产品评审会 → 问"张总这个月都提了什么" → AI从10篇纪要中聚合回答。单次会议记录价值有限，跨次聚合才是数据积累的回报。

场景三：日常速记（AI键 / 分享面板）

用户画像：任何小米手机用户，碎片化信息捕获

触发方式用户做什么系统处理产出 + 呈现规则
短按AI键（截屏）看到QQ群作业/重要信息 → 按AI键识别内容类型 → 如果是待办则提取截止时间待办 → 后台沉淀，首页不展示
短按AI键（链接）小红书好文 → 按AI键抓取全文 → AI摘要 → 保留原链接后台沉淀 → MiClaw能搜到
长按AI键（语音）走路想到idea → 长按说话录音 + 转写 + AI摘要 + 含待办则自动生成语音笔记 → 首页展示
分享面板微信收到体检PDF → 分享到笔记解析PDF → 提取关键指标 → 结构化存储后台沉淀 → 问"血糖多少"直接答

呈现规则的底层逻辑：

  • 用户主动创作 → 首页展示。长按AI键说话是用户主动发起的创作行为，形成的是一篇完整的语音笔记，应该出现在首页。
  • 系统自动采集 → 后台沉淀。短按AI键和分享面板是"随手存"行为，内容碎片化，不适合占据首页位置。它们的价值体现在：MiClaw能调用、用户问的时候能答得出来。

这两条规则解决一个实际问题：如果所有AI键存的内容都上首页，首页会被截图和链接摘要淹没，反而降低笔记列表的信噪比。

四、用户怎么消费——五种触达方式

传统笔记APP的假设是：用户会主动打开APP → 找到某篇笔记 → 阅读。但积累型产品的消费路径不应该是"搜索"——数据积累到一定程度后，应该由系统主动把价值推到用户面前。

五种方式覆盖了从"用户主动问"到"系统主动推"的完整光谱：

方式触发者机制典型场景
直接命中用户提问MiClaw在资料库目录级别就能定位答案，甚至不需要全文检索"我血糖怎么样" → 直接回答数值
自然语言检索用户提问MiClaw语义检索全量数据 → 精准回答 + 附来源"上次会定了什么" → 返回纪要+结论
智能补全用户输入触发输入关键词 → 系统推荐相关已有内容输入"上周" → 弹出"上周旅行攻略(3篇)"
系统主动提醒系统识别有时间属性的内容 → 到期主动推送通知出发前一天 → "明天CA925，08:30起飞"
笔记内深度对话用户在上下文中触发基于当前笔记内容与AI对话 → 产出新消费物看完课堂笔记 → "帮我出题" → 生成模拟题
设计原则：前两种是用户pull（主动拉取），后两种是系统push（主动推送），中间一种是半推半就。产品成熟度越高，push占比应该越大——因为数据足够多时，系统比用户更清楚"此刻应该提醒什么"。

五、首页与侧边栏：呈现逻辑

首页

首页解决的问题是：用户打开APP第一眼看到什么。原则是信噪比优先——只展示用户会主动消费的内容。

区域展示什么判定规则
主列表用户手写笔记 + 语音笔记 + AI生成的结构化内容（课堂笔记/纪要）用户主动创作 或 AI加工后的完整消费物
轻量入口待办数量提示、最近播客、纪要通知高频消费物的快捷入口
不在首页AI键短按存的截图/链接、系统自动收录的文件系统自动采集的碎片内容

侧边栏（四段式）

每段回答一个独立问题，逻辑不混用：

笔记

全部笔记（用户写的 + AI生成的结构化内容）。这是"我的内容库"。

小爱速记

AI键采集的碎片内容。独立入口，不污染主笔记列表。

AI帮你做的

所有消费物的聚合入口：待办、播客、考点、卡片、PPT。

文件夹

用户自建分组。一篇笔记只归属一个文件夹，不做多标签。

六、笔记详情页结构

每篇笔记内从上到下分三层，对应数据加工的三个阶段。用户日常只看中间层（AI加工结果），需要时才展开原文。

层级内容用户行为
原文（折叠）录音转写全文 / 截图 / 手写原稿极少展开，仅在需要逐字核实时打开
正文（默认展示）AI结构化内容：课堂总结 / 会议纪要 / 速记摘要用户日常阅读的主体——已经是加工后的结论
消费卡片基于这篇笔记产出的功能：考点 / 播客 / 待办 / PPT点击直接打开使用，每个卡片独立消费

底部固定AI对话框——用户在任何笔记详情页都能基于当前内容与AI对话，触发新的消费物生成。这是产出物的唯一生成入口，保持交互一致性。

七、竞争壁垒

这个方向为什么只有小米能做、三方APP做不了：

壁垒具体优势竞品差距
全生态无感采集手机AI键 + 穿戴录音 + 车机 + PAD，系统级入口全场景覆盖三方APP没有系统级权限，只能等用户主动打开APP
MiClaw数据底座笔记是MiClaw的长期记忆层，对话直接调用笔记数据通用AI助手（ChatGPT/豆包）没有持久化个人数据层
数据护城河用户积累三年的原始痕迹 + AI产出的个性化内容换工具数据带不走，换了也复现不了AI基于历史的理解
总结

笔记产品的演进方向：从"帮用户记住"到"帮用户产出"。

自增长 — 每个场景都在积累数据，用户无需刻意整理。
可赋能 — 每个场景都有AI产出的消费物，用户无需再加工。
中枢 — 所有数据统一沉淀，MiClaw统一调用，用户一个入口搞定。

用户不需要理解"数字资产"。他只需要感受到：用得越久，AI越好用。
