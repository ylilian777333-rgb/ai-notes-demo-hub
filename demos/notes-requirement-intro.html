小米笔记：从定位到需求

MiClaw 内容助手 · 需求导入 · 2026.05

一、我们观察到什么

过去一年，笔记 APP 的内容来源发生了结构性变化。录音转写、AI键采集、穿戴设备同步、分享面板导入——系统侧自动产生的内容，正在取代用户手写，成为笔记的主体。

但数据量的增长没有带来使用频率的增长。用户并不会因为"笔记更多了"就更频繁地打开正文阅读。一篇 2000 字的课堂转写，用户可能一次都不会通读。

用户来笔记 APP，并不是为了"阅读笔记"。

我们观察到的实际行为是：用户打开的是基于笔记生成的结果——考点清单、待办事项、播客音频。这些东西"点了就能用"，不需要再加工。

核心判断

笔记的价值不在"记住"，在"产出"。
AI 基于用户积累的数据，产出用户可直接消费的功能。笔记正文是中间过程，不是最终结果。
用户要的不是"一篇写好的笔记"——用户要的是"AI帮我做完了的事"。

这个判断引出一个设计问题：如果不让用户看到原始笔记，而是直接看到消费内容——我们的产品应该怎么构建？

以下所有需求，围绕这个问题展开。

二、产品定位

自增长可赋能的个人数字资产中枢

  1. 自增长 — 用户每次录音、拍照、说话、存链接，数据都在积累。系统侧（AI键、穿戴设备）还在持续无感采集。不依赖用户刻意整理，自然增长。
  2. 可赋能 — 积累本身没有价值，AI 把积累转化为可消费的功能才有价值。数据越多，AI 对用户理解越深，产出越精准。这是飞轮，不是存储。
  3. 中枢 — 对用户：创作入口 + 消费入口。对 MiClaw：长期记忆和数据底座——对话时调用的就是这里的数据。

关键区分：原始数据 vs. 消费物

用户输入（说/写/拍/存）→ 原始数据沉淀→ AI 理解加工→ 消费物产出→ 用户直接使用

"消费物"不是"换个格式的笔记"。 判定标准：用户拿到之后，不需要再做任何加工就能直接用。

消费物AI 加工了什么用户怎么用
结构化课堂笔记转写 → 按章节重组 → 重点标注 → 照片 OCR 嵌入打开直接看结论，不用从头整理
会议纪要录音 → 按议题分段 → 提炼结论 → 抽取待办转发纪要，待办自动跟进
待办清单录音/截图/对话 → 识别行动项 → 同步日历到期自动提醒，不怕漏事
考点 + 模拟题跨多节课聚合 → 提炼知识点 → 出题直接刷题复习
播客笔记内容 → 音频化 → 条件播放通勤时被动消费
知识卡片跨篇聚合 → 提炼观点 → 生成卡片分享到朋友圈/群
精准问答MiClaw 检索全量资产 → 基于个人数据回答"血糖多少" → 直接得到数值
为什么"课堂笔记"和"会议纪要"也算消费物？ 它们虽然仍是文字形态，但已不是原始录音转写——AI 做了重组、提炼、补充，用户看到的是结论而不是素材。原始转写折叠进"原文"区域，需要时再展开。

三、场景串联

三个场景覆盖核心用户群。每个场景遵循相同逻辑：用户输入越少越好，AI 产出越直接越好，时间跨度越长飞轮效应越强。

场景一：学生上课

18-24 岁大学生 · 每天 2-4 节课 · 核心诉求：高效记录 + 期末复习

阶段用户做什么系统做什么产出
课前点提醒卡片日历识别 → 推送提醒 → 自动新建笔记—
课中录音 + 拍板书实时转写 + 照片时间线关联—（数据积累）
课后无需操作转写 → 分章节 → 生成结构化笔记 → OCR 融入 → 提取作业课堂笔记 + 待办
期末"帮我复习高数"跨学期汇总 → 考点聚合 → 出题 → 生成播客考点 + 模拟题 + 播客
飞轮：记了一学期课 → 期末一句话 → AI 基于整学期积累产出复习方案。数据积累四个月，消费只需一句话。NotebookLM 需要手动上传文档，我们全程自动积累。

场景二：职场会议

25-35 岁白领 · 每周 3-5 次会议 · 核心痛点：待办跟丢

阶段用户做什么系统做什么产出
会前—推送：会议名 + 参与人 + 上次遗留待办—
会中录音 + 拍白板录音 + 照片时间线关联—（数据积累）
会后无需操作按议题生成纪要 → 提取待办 → 同步日历 → 通知纪要 + 待办
跨次"张总上次提了什么"MiClaw 跨篇聚合 → 精准回答 + 附来源精准回答
飞轮：10 次评审会 → "张总这个月提了什么" → AI 从 10 篇纪要聚合回答。单次记录价值有限，跨次聚合才是积累的回报。

场景三：日常速记

任何小米手机用户 · 碎片化信息捕获

触发用户做什么系统处理产出 + 呈现
短按AI键QQ群作业 → 按键识别内容类型 → 提取截止时间待办 · 后台沉淀
短按AI键小红书好文 → 按键抓取全文 → AI 摘要后台沉淀 · MiClaw 可调用
长按AI键走路说话录音 + 转写 + 摘要语音笔记 · 首页展示
分享面板体检 PDF → 分享到笔记解析 → 提取关键指标后台沉淀 · 问"血糖"直接答

呈现规则：

  1. 用户主动创作 → 首页展示。 长按 AI 键是主动创作行为，产出完整语音笔记。
  2. 系统自动采集 → 后台沉淀。 短按 AI 键 / 分享面板是"随手存"，碎片化内容不上首页，但 MiClaw 能调用。

如果所有 AI 键内容都上首页，首页会被截图和链接摘要淹没，信噪比反而降低。

四、五种触达方式

传统笔记 APP 的假设：用户主动打开 → 搜索 → 阅读。但积累型产品应该反过来——数据够多时，系统主动把价值推到用户面前。

方式触发者机制场景举例
直接命中用户MiClaw 目录级定位，不需要全文检索"血糖怎么样" → 直接答
自然语言用户语义检索全量数据 → 精准回答+来源"上次会定了什么" → 返回结论
智能补全半自动输入关键词 → 推荐已有内容输入"上周" → 弹出旅行攻略
系统提醒系统识别时间属性 → 到期推送出发前一天 → "明天 08:30 起飞"
笔记内对话用户基于当前笔记与 AI 对话 → 产出消费物看完课堂笔记 → "帮我出题"
设计原则：从 pull（用户主动拉取）到 push（系统主动推送）的光谱。产品成熟度越高，push 占比越大——数据足够多时，系统比用户更清楚"此刻该提醒什么"。

五、页面结构

首页

原则：信噪比优先——只展示用户会主动消费的内容。

区域内容判定规则
主列表用户笔记 + 语音笔记 + AI 结构化内容用户主动创作 或 AI 加工后的完整消费物
轻量入口待办数量、最近播客、纪要通知高频消费物快捷入口
不在首页AI 键短按存的截图/链接系统自动采集的碎片

侧边栏（四段式）

笔记

全部笔记（手写 + AI 生成）——"我的内容库"

小爱速记

AI 键采集的碎片——独立入口，不污染主列表

AI帮你做的

消费物聚合：待办、播客、考点、卡片、PPT

文件夹

用户自建分组，一篇笔记只归属一个

笔记详情页（三层结构）

层级内容用户行为
原文（折叠）录音转写 / 截图 / 手写原稿极少展开，仅逐字核实时打开
正文（默认）AI 结构化内容：课堂总结 / 会议纪要日常阅读主体——已是加工后的结论
消费卡片考点 / 播客 / 待办 / PPT点击直接打开，独立消费

底部固定 AI 对话框——统一入口，基于当前笔记与 AI 对话，触发消费物生成。

总结：笔记产品从"帮用户记住"演进到"帮用户产出"。

自增长 — 每个场景都在积累数据，用户无需刻意整理。
可赋能 — 每个场景都有 AI 产出的消费物，用户无需再加工。
中枢 — 所有数据统一沉淀，MiClaw 统一调用，一个入口搞定。

用户不需要理解"数字资产"。他只需要感受到：用得越久，AI 越好用。
