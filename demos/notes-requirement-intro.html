01
观察：笔记的内容在爆发，但用户不看正文
录音转写、AI键采集、穿戴同步、分享面板——系统自动产生的内容正在取代手写，成为笔记主体。
但数据量增长没带来阅读频率增长。一篇2000字转写，用户可能一次都不会通读。
用户实际打开的是什么？是基于笔记生成的结果——考点清单、待办、播客。这些东西点了就能用，不需要再加工。
CORE INSIGHT

笔记的价值不在"记住"，在"产出"。
AI基于用户积累的数据，产出用户可直接消费的功能。笔记正文是中间过程，不是最终结果。
如果不让用户看到原始笔记，而是直接看到消费内容——产品应该怎么构建？

02
定位：自增长可赋能的个人数字资产中枢
自增长

用户每次录音、拍照、说话、存链接，数据自然积累。系统侧（AI键、穿戴）持续无感采集。不依赖刻意整理。

可赋能

积累本身没有价值，AI把积累转化为可消费的功能才有价值。数据越多 → AI理解越深 → 产出越精准。飞轮，不是存储。

中枢

对用户：创作入口 + 消费入口。
对MiClaw：长期记忆层和数据底座，对话时直接调用这里的数据。

用户输入（说/写/拍/存）→ 原始数据沉淀→ AI理解加工→ 消费物产出（终态）→ 用户直接使用
"消费物"不是"换个格式的笔记"。判定标准：用户拿到后不需要再做任何加工就能直接用。

04
场景串联：端到端怎么转
三个场景覆盖核心用户群。逻辑一致：用户输入越少越好，AI产出越直接越好，时间跨度越长飞轮越强。
🎓 学生上课 · 18-24岁 · 高效记录+期末复习
阶段用户做什么系统做什么产出
课前点提醒卡片日历识别 → 推送提醒 → 自动新建笔记进入录音待命—
课中录音 + 拍板书实时转写 + 照片时间线关联—（数据积累）
课后无需操作转写 → 分章节 → 结构化笔记 → OCR融入 → 提取作业课堂笔记 + 待办
期末"帮我复习高数"跨学期汇总 → 考点聚合 → 出题 → 生成播客考点 + 模拟题 + 播客
飞轮：记了一学期课 → 期末一句话 → AI基于整学期积累产出完整复习方案。NotebookLM需要手动喂文档，我们全程自动积累。
💼 职场会议 · 25-35岁 · 待办不跟丢
阶段用户做什么系统做什么产出
会前—推送：会议名 + 参与人 + 上次遗留待办—
会中录音 + 拍白板录音 + 照片时间线关联—（数据积累）
会后无需操作按议题生成纪要 → 提取待办 → 同步日历 → 上岛通知纪要 + 待办
跨次"张总上次提了什么"MiClaw跨篇聚合 → 精准回答+附来源精准回答
飞轮：10次评审会 → "张总这个月提了什么" → AI从10篇纪要聚合回答。单次记录价值有限，跨次聚合才是积累的回报。
📱 日常速记 · 全用户 · 碎片化捕获
触发操作系统处理产出 + 呈现
短按AI键QQ群作业 → 按键识别待办 → 提取截止时间待办 · 后台沉淀，不上首页
短按AI键小红书好文 → 按键抓全文 → AI摘要 → 保留原链后台沉淀 · MiClaw可调用

分享面板体检PDF → 分享到笔记解析 → 提取关键指标后台沉淀 · 问"血糖"直接答
呈现规则：用户主动创作（长按说话）→ 首页展示。系统自动采集（短按/分享）→ 后台沉淀。
原因：如果碎片内容全上首页，信噪比会被截图和链接摘要拉低。

笔记详情页：三层结构
原文折叠 — 录音转写/截图/手写原稿。极少展开，仅逐字核实时打开。
正文默认展示 — AI结构化内容（课堂总结/纪要）。日常阅读主体，已是加工后结论。
消费卡片可展开 — 考点/播客/待办/PPT。点击直接打开，独立消费。
AI对话框底部固定 — 统一入口：基于当前笔记对话，触发消费物生成。
07
总结

笔记产品演进方向：从"帮用户记住"到"帮用户产出"。

自增长 — 每个场景都在积累数据，用户无需刻意整理。
可赋能 — 每个场景都有AI产出的消费物，用户无需再加工。
中枢 — 所有数据统一沉淀，MiClaw统一调用，一个入口搞定。

用户不需要理解"数字资产"。他只需要感受到：用得越久，AI越好用。
