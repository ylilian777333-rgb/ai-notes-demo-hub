12 个用户痛点与洞察设计

从痛点往下拆，不从交互框架往下讲。每个痛点走三层：现象 → 他真正要的是什么 → 我们做什么，并且每个痛点单独配一条完整交互链路——12 条链路、48 屏，每条都走到跨应用的那个落地动作（进待办中心、写进日历、存进这门课、导出给别人）。笔记本身还是笔记；洞察里的格子是用户进到笔记里必须能拿到的东西。交互框架放最后，由这 12 个方案倒推出来。

00

先说清「洞察」里放的是什么

洞察不是一个新的笔记列表。它放的是长出来的可消费单元——一个格子。一个格子进去，是一件事的完整结果，不是那几条原始记录。

场景一个格子是什么格子怎么来的
待办日程 今天 / 本周 格子是固定的时间窗，内容从别处流进来（笔记正文、语音、图片里认出的待办）。分栏不会变，里面的内容每天变。
想法随记 工作想法 / 生活随记 / 一轮访谈 / 钓鱼 格子完全由用户记的内容长出来。他记什么，长出什么；没记过的主题不会有格子。
学习备考 一门课 格子由外部结构确定：课程表里有几门课，就有几个格子。哪堂课的材料进哪个格子是确定的。

一级分栏是定的，格子是长出来的。

所以洞察页不需要用户建文件夹、不需要他选分类。他只管记，格子自己出现，出现了推送告诉他。

01

待办日程已定：进洞察

用户不在笔记里读待办。他要的只有一件事：现在该做什么，别错过。

先纠一处：“没做完的必须自己再誊一遍”是纸笔时代的痛点，属于类比，不是今天手机上的问题。今天真实的问题拆成下面 P1–P4：认不出来、散在多处、会沉底、想不起为什么记。
P1
现象

记在笔记正文里的待办，从来没被当成待办

开会时顺手写下“下周五之前把方案发给老王”，它就是正文里的一行字。到了周五没有任何提醒。用户要么自己再去待办应用录一遍，要么就漏了。语音转写出来的那一大段里，这类句子更是彻底埋着。

真实需求

我写下来的时候就当我在安排一件事，别让我再录第二遍。

方案

正文与转写里自动抽取待办项，用户确认后成立

  • 正文、语音转写、图片、手写里的待办句自动抽出来，连带时间一起
  • 抽出来的每一条保留回原句的链接，不脱离上下文
  • 抽错了能直接取消这一条，不影响原文

依赖 / 待定　置信度低于阈值只提示不自动建；抽取准确率待跑数

P2
现象

待办散在笔记正文、待办中心、日历三处，没有统一的今天

笔记里勾选框一份，系统待办一份，日历里还有一份带时间的。用户要在三个地方来回切，才拼得出今天到底要做什么。哪件事在哪儿，他自己也记不清。

真实需求

给我一个地方，打开就是今天全部要做的事。

方案

今天这个格子只做汇总，不再造第四份数据

  • 笔记里认出的、待办中心里的、日历里带时间的，汇到今天这一个格子里看
  • 数据仍在原来的地方，笔记不另存一份，避免三处不一致
  • 要写回待办中心或日历时，先让用户确认，不静默写外部

依赖 / 待定　与系统待办中心、日历的读写接口与数据归属边界

P3
现象

没做完的会沉底，第二天不会自己出现

待办跟着它所在的那篇笔记按时间排。昨天那篇今天已经沉到列表下面，用户打开首页看不到它。要靠自己想起“我好像还有件事”，再往回翻。越久以前的越翻不到。

真实需求

没做完的事，明天该主动站到我面前，而不是等我想起来。

方案

自动结转到今天并排在最前，标出顺延了几天

  • 未完成的每天自动结转到今天，排在新事项前面
  • 标出它是从哪天顺延过来的、压了几天
  • 连续顺延多次的给出口：改期，或者标记不做了——不让它无限期挂着

依赖 / 待定　连续顺延几次开始提示、出口文案待定

P4
现象

看到那条待办，想不起当初为什么记它

“确认报价口径”——这是哪个客户、当时在哪次会上说的？一条干巴巴的待办脱离了当时的上下文，用户看着它得先花时间回忆，甚至干脆放着不动。

真实需求

让我一眼知道这件事的来处，必要时能回去看当时说了什么。

方案

每条待办带来源，能回到被记下的那一句

  • 待办上带来源标识：哪篇笔记、哪次录音、哪天
  • 点一下回到被记下的那一句原话，不是只跳到笔记开头
  • 来自录音的，直接跳到录音里对应的时间点

依赖 / 待定　转写需保留句级时间戳

02

想法随记访谈属于这里，不单独立品类

用户自己记下的内容延伸出来的都在这里：工作上的思考、生活随记、兴趣，以及一段时间里为同一件事做的多次记录。

P5
现象

工作和生活混在同一条时间流里

随口记的东西按天往下排。周一的排期思考、周末看到的一家店、晚上的一句感想挨在一起。两周后往回翻，得一条条看才知道哪条是哪件事。工作场合翻到私人内容也不合适。

真实需求

工作的和生活的别放一起，我在什么状态下就只看那一类。

方案

一级分栏按语境固定，记进来自动归栏

  • 一级分栏是定的（工作 / 生活），不靠用户维护
  • 记的时候不用选，存下自动归栏；归错了一下能改
  • 兴趣这类（钓鱼、游戏）作为格子长在生活下面，不占一级分栏

依赖 / 待定　兴趣是否需要独立一级分栏、按内容量按需显示，待判

P6
现象

同一件事记了很多次，这些记录之间没有任何关系

一个月里为同一个问题记过五六次，每次都是一条独立笔记。出差三天做了七场访谈，就是七段互不相干的录音。系统不知道它们是一件事，用户自己也不会去把它们串起来。

真实需求

为同一件事记的东西，应该自己聚到一起，并且告诉我它成形了。

方案

自动聚成一个格子并自动起名，聚好了推送

  • 同一件事的多次记录聚成一个格子，名字自动起好（西安访谈、这次装修）
  • 聚好主动推送，不靠用户回来发现
  • 判不准的先保持原样，不硬凑一个格子

依赖 / 待定　格子成立的门槛（几条、多久内）待定

P7
现象

东西聚起来了，用户不知道在这儿能干什么

就算把二十几条相关记录摆在一起，用户面对的还是一堆自己写过的字。想接着往下想，得自己先看一遍、再把要点复制出来喂给 AI。多数人到这一步就停了。

真实需求

我想接着聊，让思路更清楚，别让我先做准备工作。

方案

进去直接是对谈，内容已经挂上，不是一个「问小爱」按钮

  • 点进格子第一件事就是对谈，界面上显性标出已挂载了这个格子的多少条内容
  • 开场先给出这段时间反复出现的几处，用户不用自己回想
  • 是可持续的会话，上次聊到哪里留着，下次接着聊

依赖 / 待定　需小爱侧支持把格子内容作为上下文挂载并保持会话

P8
现象

聊出来的结论拿不出去

对谈里理清楚了，但要发给同事、要在会上讲，还是得自己重新排成一份文档或几页 PPT。笔记里的东西最后停在纯文本上。

真实需求

理清楚的东西要能直接变成我拿得出手的那一份。

方案

默认正文不预生成，需要时显性转成别的形态

  • 默认给整理好的正文，不预先生成 PPT 那些（成本控住）
  • 需要时一键转成 PPT / PDF / Excel，由用户发起
  • 每条结论能点回原话；里面的下一步能直接进待办

依赖 / 待定　本版开放哪几种形态需圈定

03

学习备考

这个场景的链路从笔记之外开始：课程表在相册里被认出来、课在日历里、上课时录音。笔记这边要做的是把一堂堂课变成一门课。

P9
现象

一门课的材料散在四五个应用里

课上录音在笔记，老师的课件在群里，电子教材是下载的文件，往年真题是另一个文件。存的时候还要想存到哪个文件夹。复习时在几个应用之间来回找，找的时间比看的时间长。

真实需求

属于这门课的东西，我存的时候不用管去哪，要用的时候都在一起。

方案

四类来源自动归位：保存即归位，不弹文件夹选择

  • 课堂录音、课件、电子教材、往年真题自动归到同一门课下
  • 群里发的文件存下来直接落到对应课程，不弹「存到哪个文件夹」
  • 归错了在格子里一下能改

依赖 / 待定　文档类内容的课程归属判定准确率待跑数

P10
现象

十次有三次忘了开录音，而且忘了就永久没了

一堂课两小时，学生经常忘记点录音，或者上到一半才想起来。跟其他遗漏不一样：这个是不可逆的，那段课的内容再也补不回来，后面所有整理都建立在一段缺口上。

真实需求

该录的时候自己录上，我忘了也别真的丢。

方案

课程日程到点自动录音，端侧常录最近几分钟接上忘记的那段

  • 日历里的课程日程标为自动录音，循环生效，到点自己开始
  • 端侧低功耗常录最近几分钟，中途才点开也能接上前面那段
  • 录完自动归到这门课，不用用户操作

依赖 / 待定　日历提供课程日程与循环规则；常录时长、功耗存储与隐私边界待技术侧与合规评估

P11
现象

材料越全，考前越无法下手

十几堂课的录音、几十页课件、三份真题都在，考前只剩两天。东西越齐，用户越不知道从哪开始。他要的不是录音也不是逐字转写，是这门课考什么、我到底会不会。

真实需求

直接告诉我该看什么、考什么，再让我确认自己会了没有。

方案

进这门课先给精讲、快讲、一套测试卷

  • 进去是精讲 / 快讲 / 出一套测试卷，不是一串课堂录音列表
  • 出题照这门课往年真题的风格来，每题标出自哪堂课、能回到原文那一段
  • 答错的按间隔重复再考；只考这门课存进来的内容
  • 原始资料退到次级入口

依赖 / 待定　能拆出判定步骤的考点占比待跑数，过低则本版先只出考点清单

P12
现象

作业和这门课是断开的

老师留的作业要结合这几堂课的内容做，用户得先找到对应几堂课的笔记再一边翻一边写。写完了，下次看日程也不知道这门课的作业到底交了没有。

真实需求

写作业的时候课上的内容就在手边，写完了这件事要能被记住。

方案

作业归入这门课，写的时候整门课的材料已挂载，写完回链日程

  • 存进来的作业自动识别并归到这门课，标出未完成
  • 写的时候对谈已挂载这门课全部材料，不用自己找
  • 写完的进度和链接回到课程日程里

依赖 / 待定　日历侧承接作业进度与笔记入口

04

其余存进来的内容

旅行攻略、一次临时会议、随手收藏的资料。它们不需要另起一套形态——它们是格子长出来的土壤：今天还不成形，攒够了就是下一个格子。

不为「其余内容」单独设计一套形态。

用的是想法随记那一套：判不准的先原样放在「笔记」里，同一件事攒够了就自动聚成格子、自动起名、推送告知，进去一样能对谈、一样能转成拿得出手的一份。三个场景做透，这条路自然就通。

这一层怎么处理
判不准的内容 保持原样放在「笔记」这一侧，不硬归类、不硬凑格子。用户随时能自己找到。
攒够了的 自动聚成格子并起名（这趟成都、家里装修、这个项目），进入洞察，与三个场景共用同一套聚合与生成。
原有文件夹与单篇 原样保留在「笔记」这一侧，编辑与查找方式不变。洞察是新增的一侧，不动老用户的习惯。
05

交互框架：每一条都对着上面的方案

框架不是先定好再往里塞需求。上面 12 个方案要落地，就必然要求下面这几件事。

这一层怎么定因为哪个方案要求
底 tab 两个 洞察（格子在这里）／笔记（原始记录与原有文件夹）。两者不混在同一个 tab。 P2 今天要一处看全 · P6 格子要能被看见 · 04 原有文件夹原样保留
洞察页 = 一级分栏 + 横滑格子 三个一级分栏固定；栏内横向滑动，每个格子是一件事的完整结果，名字自动起好。参照相册的组织与呈现。 P5 分栏按语境固定 · P6 格子自动聚成并起名 · 00 分栏是定的、格子是长出来的
进格子第一屏是对谈或行动 随记类进去是对谈并显性挂载；学习类进去是精讲 / 出卷；待办类进去是今天该做的事。原始内容退到次级入口。 P7 别让用户先做准备工作 · P11 材料齐了要先给该看什么
默认正文，形态按需转 格子里默认给整理好的正文，不预生成；需要时显性转 PPT / PDF / Excel。 P8 结论要拿得出去，同时控住生成成本
创建入口两个 一个加号建文字笔记，另一个进录音。第三个按钮去掉。 P1 随手记就要能被认出来 · P10 录音是学习场景的主入口
分类只留一层 顶栏分类 + 侧边栏分类 + 底 tab 三层过于复杂。顶栏与侧边栏都收掉，分类只留洞察页的一级分栏；原有文件夹进「笔记」。 P9 存的时候不该弹文件夹 · P5 分栏由系统固定而非用户维护
成形就推送 格子聚好、一门课成形、结论生成完成，主动推送。 P6 聚好了要告诉我 · P10 录完自动归位 · P12 进度要被记住
06

已定与待判

已定 · 待办日程进洞察 作为一级分栏，格子是固定时间窗（今天 / 本周），只做汇总不另存一份数据。
已定 · 访谈属于想法随记 不单独立一个品类。它就是「为同一件事的多次记录聚成一个格子」这条通用能力的一个例子。
待判 · 洞察页还没有格子的时候长什么样 格子是长出来的，新用户和记得少的用户第一次打开就是空的。待办日程这一栏不依赖积累（有一条待办就有内容），可以先撑住第一屏；想法随记和学习备考要等内容攒够。要定的是空的时候给什么、多久能长出第一个格子。需要用研拿一个数：存量用户里有多少人现在就能出至少一个格子。
待判 · 兴趣栏是否需要独立一级分栏 钓鱼、游戏这类现在作为格子长在「生活」下面。如果某类内容量很大，是否按需升为一级分栏？我倾向不升，一级分栏保持固定两三个。
待判 · 格子成立的门槛 几条内容、多长时间内算「为同一件事记的」？门槛低了会长出一堆空洞的格子，高了用户等不到。需要拿存量内容跑一遍再定。
待判 · 端侧常录的隐私边界 常录最近几分钟是 P10 的关键。录多长、只在课程日程时段还是常开、数据只在端上留多久，需要先和技术侧与合规对一个可行范围，再定交互怎么呈现。
待判 · 顶栏和侧边栏收哪个 我的建议是两个都收，分类只留洞察页的一级分栏。需要你确认。
待判 · 第一个 tab 叫什么 洞察 / Inside / 合集。这一版材料里统一用「洞察」，最终名字你定。
