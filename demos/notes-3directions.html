一、产品定义

问题

AI内容越来越多，首页被冲，用户写笔记的意图被稀释。

解法

笔记 = 所有内容的本体（用户有动作产生的）
资料库 = 按类型聚合查看的视图（不是另一个存储空间）

核心规则：看用户有没有动作

用户有动作（说/点/写/录/分享）→ 进笔记

用户零操作，系统自动产出 → 仅在资料库

AI生成物 → 双记：笔记里是附件，资料库里按类型聚合可见

二、笔记类型（用户有动作）

用户在内容产生时有主动行为。数据本体在笔记。

类型用户动作文件夹
手写/打字笔记在APP内新建并输入用户自建文件夹
AI键速记长按AI键+说话自动归类到用户文件夹
穿戴录音手表/戒指/耳机录音内置"穿戴"文件夹
对话存入说"记到笔记/存到笔记"自动归类到用户文件夹
外部分享存入微信/浏览器点分享自动归类到用户文件夹

文件夹结构

系统预置：穿戴（设备录音，来源特殊需集中回顾）

用户自建：工作 / 学习 / 生活 / ...

AI键速记不单独文件夹，通过自动归类进用户文件夹

chips = 全部 + 穿戴 + 用户自建文件夹

三、资料库视图（3类）

资料库不是另一个存储空间，是按类型聚合查看的快捷入口。

聚类包含数据位置
📞 通话录音通话纪要仅资料库（用户零操作，首页不出现）
✦ AI生成物PPT/播客/研究/网页双记（笔记附件+资料库聚合）
📋 自动整理日报/周报仅资料库（系统定时，首页不出现）

一级Chips：全部 / 通话录音 / AI生成物 / 自动整理

点"AI生成物"进入二级：全部 / PPT / 播客 / 深度研究 / 网页

双记逻辑（AI生成物）

用户在笔记A里点"生成PPT" →

• 笔记A详情页：底部出现附件卡片"技术选型.pptx"

• 资料库"AI生成物"：能看到这个PPT（指向同一份数据）

用户找PPT有两条路，但数据只有一份。

四、分类判断规则

核心规则：用户在内容产生时有没有动作

内容用户动作归属
手写/打字主动输入笔记 · 用户文件夹
AI键速记主动按键说话笔记 · 自动归类到用户文件夹
穿戴录音主动按手表录笔记 · 穿戴文件夹（预置）
对话"记到笔记"主动指令笔记 · 自动归类
微信分享到笔记主动点分享笔记 · 自动归类
笔记内点"生成PPT"主动点按钮笔记附件 + 资料库视图
通话纪要零操作仅资料库 · 通话录音
系统日报/周报零操作仅资料库 · 自动整理

为什么用"有没有动作"

✕ "是否编辑过" — 改了一个字就换地方，用户不理解

✕ "内容形式" — 同样是链接，用户粘贴的和系统收纳的感知不同

✕ "来源" — 微信分享进来的，用户觉得是"我存的"

✓ "有没有动作" — 我做了事才有的=我的；我没做事它自己出来的=系统的

五、用户场景验证

"我让小爱记了一段话，在哪？"
→ 笔记里。用户说了"记到笔记"= 有动作。

"我从微信分享了一篇文章到笔记，在哪？"
→ 笔记里。用户主动点了分享 = 有动作。

"系统自动生成的通话纪要在哪？"
→ 资料库。用户零操作，系统自己做的。

"我在笔记里点了生成PPT，在哪找？"
→ 两个地方都能找到。源笔记里有附件卡片；资料库"AI生成物"里也能看到。

"我长按AI键录了一段话，在哪？"
→ 笔记里。用户主动按键 = 有动作。

"系统每天自动生成的日报，在哪？"
→ 资料库。用户零操作，定时自动跑。

六、三方向对比

A Pill分流B 侧边栏C 聚合卡
老用户影响学1个Pill学新结构零
首页干净完全干净完全干净卡片占位
资料可发现一键切Tab开侧边栏点展开
开发成本中大小
扩展性加chip即可无限放不下

结论：OS4推荐A，下版本演进B。C作为兜底。
