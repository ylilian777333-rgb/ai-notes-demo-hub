02内容的获取与理解

##现状：只有笔记内能记，存进来之后系统看不见里面是什么

［待补图］0 字笔记
拍投影 / 拍工单 / 纯录音
正文 0 字，最长一条录音 91 分钟
［待补图］用户自己排版
手写连加算式、空格对齐
账目全是手写连加，没有人用表格
［待补图］标题命名
「1」「2」「0912」
多数人不建文件夹，靠标题加序号加日期归类

##三个关键

1. 收得全
各端各处都能记，别处的内容也能一键存进来
2. 理得准
0 字笔记要补出内容，字段抽得对、不准就不硬归
3. 拿得出
要用时给的是结果，且能回溯到原文

#实现方案

##补出内容的三种方式

方式一：端侧读图 + 听录音，把 0 字笔记补成可读正文
主推
方案原理
拍投影 / 录音
端侧读图 + 转写
合成正文，段落标来源
参与聚类与检索
优：
- 敏感内容不出设备
- 断网也能用，无调用成本
- 每段可回溯到投影第几张、录音第几分钟
劣：
- 长录音耗时，需后台跑
- 端侧模型能力受机型限制
依赖：端侧模型（算法侧）、后台长任务（系统侧）
方式二：系统级入口一键存，内容进来即建索引
主推
方案原理
AI 键 / 悬浮球 / 分享
存入确认卡
落库并建索引
四类首页归位
优：
- 用户一步就存，成本最低
- 存什么由用户决定，口径清楚
- 入口可埋点，能评估哪些入口真被用
劣：
- 识屏、跨端入口依赖外部团队排期
依赖：小爱识屏、系统分享、互联与可穿戴、汽车
方式三：三方生成的内容写进笔记
兜底
方案原理
三方对话生成网页 / 文档
点「存进笔记」
来源留痕
与自记内容同一套理解链路
优：
- 对接入方也是内容出口，谈得动
- 不改用户习惯，多一条进来的路
劣：
- 需要对方改代码，覆盖多少家取决于商务节奏
商务进度：待拉通，优先谈内容产生量大的应用

#产品方案

##0 字笔记：从看不出存了什么，到能读、能搜、能被调用

Before
［待补图］笔记详情
正文空白，只有一张投影图和一条 91 分钟录音
标题「0912」
After：补出正文并标注来源
［待补图］笔记详情
正文按段落补出
每段前标「来自投影第 1 张」「来自录音 08:15」

##理解不准时怎么办

情况处理用户看到什么
置信度 ≥ 0.85自动归到品类与主题直接在主题下看到这条
0.60 – 0.85不自动归，等用户点一下确认存入时出现可点的建议标签
低于 0.60落未分类，不硬归首页未分类入口带数字角标
图无文字、录音无人声不生成正文，保持附件态「这条里没找到可以补出来的内容」
用户说这段不对该段折叠回原附件，记为负样本段落级「这段不对」可点
